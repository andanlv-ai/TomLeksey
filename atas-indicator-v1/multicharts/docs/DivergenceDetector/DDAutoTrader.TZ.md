# ТЗ: DDAutoTrader v1.0 — виртуальный советник по дисбалансам

Составлено 2026-09-26 по брифу `DDAutoTrader.BRIEF.md` (ссылки на ID — оттуда).
Исходник: `atas-indicator-v1\multicharts\src\DDAutoTrader.Strategy.CS` (дорабатываем v0.1, Р-3).

## 1. Назначение
Стратегия MultiCharts .NET на часовом графике 6E, 6B, 6J (данные CQG). Реальные ордера не отправляет.
Ловит дисбалансы DivergenceDetector, открывает виртуальные сделки со стопом и тейком за фракталами
и пишет в файлы каждый дисбаланс, ход цены после него и каждую сделку. По файлам Claude разбирает
статистику и меняет правила отбора (Р-1, Р-4). Мерило — пипсы и доллары по каждой валюте (Р-15, Ф-24).

## 2. Что в v0.1 уже есть и что не так
| Есть в v0.1 | Что меняем |
|---|---|
| Читает только сигнал дивергенции (`Plots[0]`) | + streak (`Plots[1]`), Р-2 |
| Стоп 10 и тейк 20 пунктов | стоп и тейк за фракталами, Р-13 |
| Стоп и тейк проверяются по цене закрытия бара | проверка по High/Low бара, порядок — по минуткам (В-14) |
| Файл дописывается при каждом запуске, история задваивается | без дублей (Р-14) |
| Один файл, пункты | набор файлов, пипсы и доллары (В-15, В-18) |

## 3. Сигналы (Р-2, Р-9)
Сигнал считается только на закрытии часового бара (Ф-25). Три вида, у каждого своя «книга»
(отдельная виртуальная позиция на инструмент):

| Книга | Условие | Направление |
|---|---|---|
| `DIV` | `Plots[0]=1`, цвет Lime / Red | Lime — покупка, Red — продажа |
| `STR_WITH` | `Plots[1]≠0`, цвет Orange / Blue | по дельте: Orange — покупка, Blue — продажа |
| `STR_AGAINST` | тот же streak | против дельты: Orange — продажа, Blue — покупка |

Книги нужны, чтобы streak торговать в обе стороны одновременно и считать пипсы каждого вида отдельно.

## 4. Сделка
- **Вход** по цене закрытия бара с сигналом (П-2). Только понедельник–пятница по времени Парижа (Ф-11).
- **Фрактал** — классический, 5 баров: средний бар выше (ниже) двух слева и двух справа (Ф-15).
  Берём только подтверждённые, то есть закончившиеся минимум 2 бара назад (Р-13).
- **Стоп**: ближайший по времени подтверждённый фрактал против сделки, который лежит за ценой входа;
  стоп ставим на `FractalOffsetTicks` тиков за ним (Ф-14).
- **Тейк**: ближайший по времени подтверждённый фрактал по ходу сделки, который лежит за ценой входа,
  тот же отступ. Поиск назад не дальше `FractalLookback` баров.
- Нет подходящего фрактала — входим всё равно (Р-7), поле пустое, в строке пометка `NO_SL` / `NO_TP`.
- Стоп и тейк не двигаются (Р-10).
- **Выход**: цена коснулась стопа или тейка (High/Low бара); выход ровно по уровню.
  Встречный сигнал той же книги — закрыть по закрытию бара и сразу открыть обратную сделку (Р-8).
  Сигнал в ту же сторону — только записать (П-3).
- **Стоп и тейк в одном часовом баре** (С-1, В-14): порядок берём по минутному потоку данных
  (второй поток на графике, `BarsOfData(2)`). Минуток нет — считаем стопом и ставим `AMBIGUOUS=1`.

## 5. Когда не входим (сигнал всё равно пишется, с причиной пропуска)
| Причина | Правило |
|---|---|
| `NEWS` | закрытие бара попадает в окно 14:30–15:30 или 19:00–21:00 по Парижу (Р-12) |
| `ZERO_DATA` | хотя бы у одного бара окна сигнала нет данных о покупках и продажах (К-6) |
| `WEEKEND` | суббота, воскресенье по Парижу |
| `RULES` | вид сигнала выключен в файле правил (раздел 7) |
| `IN_POSITION` | в книге уже открыта сделка в ту же сторону |

Время Парижа считать из времени графика через `TimeZoneInfo` ("Romance Standard Time"),
тогда переход на зимнее время учтётся сам (С-5).

## 6. Файлы — папка `D:\TradeLog\` (В-18)
Все файлы CSV, разделитель — запятая, время — время графика и отдельной колонкой время Парижа.

| Файл | Строка | Когда пишется |
|---|---|---|
| `signals_<SYM>.csv` | один дисбаланс | сразу на закрытии бара |
| `moves_<SYM>.csv` | ход цены после дисбаланса | через 24 бара после сигнала |
| `trades.csv` | одна закрытая сделка | при закрытии |
| `runs.csv` | запуск и остановка советника | START / STOP |
| `rules.csv` | правила отбора | пишет Claude, читает советник |
| `rules_history.csv` | правка правил и её результат | пишет Claude (Р-5) |

**`signals_<SYM>.csv`** (П-1, В-17): `Time, ParisTime, Symbol, SignalId, Book, Dir, Delta,
Volume, RangeATR, Session, News, ZeroData, Entry, SL, TP, SL_pips, TP_pips, Taken, SkipReason,
Source, RulesVersion`.
`Session` — Азия 00:00–08:00, Европа 08:00–14:30, Америка 14:30–22:00, иначе `OFF` (по Парижу).
`RangeATR` — размах бара / `this.AverageTrueRange(14)`.
`Source` — `HIST` (расчёт по истории) или `LIVE` (живой бар).

**`moves_<SYM>.csv`**: `Time, ParisTime, Symbol, SignalId, Up1, Dn1, Up3, Dn3, Up6, Dn6, Up12, Dn12, Up24, Dn24,
HypoResult, HypoPips, HypoAmbiguous`. `UpN`/`DnN` — сколько пипсов цена прошла вверх и вниз от входа за N баров.
`HypoResult` — что было бы с этим сигналом по его стопу и тейку за 24 бара (`TP` / `SL` / `NONE`),
даже если сделку не открыли. По этому полю Claude пересчитывает любое правило задним числом (Р-5, К-2).

**`trades.csv`**: `CloseTime, ParisTime, Symbol, SignalId, Book, Dir, OpenTime, OpenPrice, SL, TP,
ClosePrice, Exit (TP/SL/SIGNAL), Pips, Usd, Ambiguous, Source, RulesVersion`.
`Usd = разница цен × Bars.Info.BigPointValue − CommissionUsd` (В-15).

**Без дублей** (Р-14): при запуске советник читает время последней строки каждого файла
и пишет только бары новее этого времени. История при первом запуске пишется целиком с `Source=HIST` —
это сразу даёт точку отсчёта (К-4).

## 7. Правила отбора (`rules.csv`)
Формат: `Symbol, Book, Enabled` (например `6E,STR_AGAINST,0`). `*` — любой инструмент.
Файла нет — все книги включены. Советник читает файл при запуске; номер версии правил —
строка `#version,N`, пишется в каждую строку сигналов и сделок.
Новые виды фильтров (сессия, размах, дельта) добавляем, когда разбор покажет, что они нужны.

## 8. Разбор и правка правил (Р-1, Р-4, Р-5, В-16)
1. По запросу или раз в день Claude читает `D:\TradeLog\` и показывает: по каждому инструменту и книге —
   число сделок, доля прибыльных, пипсы, доллары; разрез по сессии, новостям, пропускам.
   Отдельно — обзор последних дисбалансов: когда, куда пошла цена, что сделал советник, итог (К-10).
2. Правку правил Claude проверяет по `HypoResult`: дни делятся по дате на 70% (подбор) и 30% (проверка).
3. Правка принимается, только если на обеих частях плюс в пипсах и сделок не меньше 30 (С-4).
4. Правка пишется в `rules.csv` (новая версия) и в `rules_history.csv`:
   `Date, Version, Change, Reason, PipsBefore, PipsAfter, Trades`.

## 9. Параметры (Input)
| Параметр | По умолчанию | Смысл |
|---|---|---|
| `LogDir` | `D:\TradeLog\` | папка файлов |
| `PipSize` | 0.0001 | размер пипса; для 6J задать на графике — проверить |
| `CommissionUsd` | 0 | комиссия за контракт туда и обратно — ждём цифру от пользователя |

| `FractalLookback` | 100 | насколько далеко назад искать фрактал |

## 10. Проверка готовности
1. Сборка в PowerLanguage Editor: 0 ошибок.
2. На графике 6E H1 с минутками вторым потоком после запуска появились все файлы из раздела 6.
3. Два перезапуска подряд — число строк в файлах не меняется.
4. Три сделки сверены глазами с графиком: вход, фракталы стопа и тейка, выход.
5. Сигнал в окне новостей записан с `SkipReason=NEWS`, сделки нет.
6. Бар, где задеты и стоп, и тейк, решён по минуткам; без минуток — `AMBIGUOUS=1`.

## 12. Толкования модели — поправить, если не так
- Три книги вместо одной позиции (раздел 3).
- «Ближайший фрактал» — ближайший по времени, а не по цене.
- Окна новостей действуют каждый рабочий день, а не только в дни новостей.
- Границы сессий (раздел 6).
- Комиссия 0, пока нет цифры.

## Не входит в v1.0
Реальная торговля; смена контракта (С-7); фильтры кроме вкл/выкл книги; автоматический разбор без запроса.
