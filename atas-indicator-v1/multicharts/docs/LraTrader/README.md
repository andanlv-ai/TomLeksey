# LraTrader — как устроен и как запустить

Состояние на 2026-10-27. Исходное ТЗ — [tz.md](tz.md); где они расходятся, верно это описание.
Правила автора — [../DivergenceDetector/PATTERNS.md](../DivergenceDetector/PATTERNS.md), ссылки `В2 21:01` = видео 2, минута 21:01.

LraTrader — стратегия MultiCharts .NET для часового графика валютных фьючерсов CME. Реальных ордеров нет:
советник открывает виртуальные сделки, рисует их на графике и пишет всё в CSV.

## 1. Настройка графика

Один часовой график, источник CQG, например `BP6Z26`, 1 Hour.

| Ряд | Что | Volume Profile (Format → Instrument → Volume Profile) |
|---|---|---|
| Data1 | основной `BP6Z26` | Show VP, Total Volume, **Ask vs Bid Traded Delta**, Every 1 Bar |
| Data2 | тот же `BP6Z26`, 1 Hour (Insert → Instrument), SubChart #2 | Show VP, Total Volume, **Up vs Down Tick Delta**, Every 1 Bar |

- Data1 даёт дельту по объёму (аск/бид), Data2 — дельту по сделкам (ап/даунтик). Это две дельты автора (В2 21:01).
- Профиль выключать нельзя: советник читает из него дельту. Чтобы он не мешал, Appearance → Transparency = 100.
- Нет Data2 — советник не считает и пишет в `runs.csv` строки `VP_WAIT`.
- Build Volume on (Trade Volume / Tick Count) на профиль истории не влияет: CQG отдаёт барам UpTicks/DownTicks = 0, всё берётся из профиля.
- Потиковая история у CQG — около месяца. Бары старше профиля не имеют, советник их пропускает.

**Установка.** Исходники — `src/lra/*.cs`; единый файл `src/LraTrader.Strategy.CS` собирает `src/lra/tools/bundle.sh`
(руками его не править). Файл копируется в
`C:\ProgramData\TS Support\MultiCharts .NET64 Special Edition\StudyServer\Techniques\CS\LraTrader.Strategy.CS`;
MultiCharts сам перекомпилирует его и пересчитает график. Затем Insert → Strategy → LraTrader.

## 2. Как принимается решение

Раз в час, на закрытии бара.

1. **Профиль бара.** Ask/Bid по ценам из Data1, Up/Down из Data2. `ItemForBar(Bars.FullSymbolData.Current - 1)`:
   без `-1` MultiCharts отдаёт профиль следующего бара (сверено по High/Low).
2. **Диапазоны ЛРА** (`CoreRanges.cs`). Самое длинное окно до текущего бара высотой ≤ `MaxRangePips`,
   не короче `MinRangeBars`, из них ≥ `MinActiveBars` в Европе/Америке. Рождается, когда бар закрылся за окном.
   POC — цена с наибольшим объёмом. Отработан, когда цена вернулась к POC; забыт через `MaxRangeAgeBars`.
3. **Толпа** (`CoreImbalance.cs`, режим `CrowdMode = CUM`).
   - Кумулятивная дельта по сделкам за последние `CumLookback` часов; начало роста — её минимум (толпа покупает)
     или максимум (продаёт), не ближе `CumMinBars` к текущему бару.
   - Вес: рост дельты / объём с начала роста ≥ `CumWeight` (пример автора: 180 из 300, В2 22:05).
   - Дельта по объёму за то же время не против: обратная доля ≥ `MinShare` — противоречие, сделки нет (В1 01:35).
   - Перекос на нескольких ценах: ≥ `MinLevels` цен, где (Ask−Bid)/(Ask+Bid) ≥ `LevelImbPct` в сторону толпы (В4 05:23).
   - Цена за время роста не вышла за хай (лоу) бара начала роста (В4 02:28).
   Режим `WINDOW` — прежний: окно `ImbBars` часов, доля от объёма дня, допуск цены `StallAtr`·ATR, есть сценарий D.
4. **Вход** против толпы по закрытию бара (сценарий A, В4 02:41).
5. **Стоп и тейк** (`CoreLevels.cs`). Стоп — за ближайший по времени фрактал за ценой входа + `OffsetTicks`;
   фрактал — бар, чей хай выше (лоу ниже) `FractalBars` соседей с каждой стороны, не дальше `SwingLookback` баров.
   Тейк — ближайший фрактал в сторону сделки, но не дальше `MaxTakePips`. Стоп дальше `MaxStopPips` — пропуск `NO_LEVEL`.
6. **Фильтр ЛРА.** Сделка прочь от POC ближайшего активного диапазона — пропуск `AGAINST_LRA` (В4 07:33).
   Если POC дальше `LraMinDistPips` и не дальше `DayTargetShare` × средний дневной ход — второй контракт с целью POC
   (В4 07:10, В1 01:08). Дневной ход — средний размах дня по Парижу за `AtrPeriod` дней.
7. **Запреты.** Выходные, новости `NewsWindows` (время Парижа), одна позиция на книгу (`IN_POSITION`).
8. **Сопровождение** (`CorePositions.cs`), на каждом закрытом баре:
   - `SL` / `TP` по High/Low бара; стоп и тейк в одном баре — считается стоп, `Ambiguous = 1`;
   - `DISSOLVED` — перекос от начала окна исчез или перевернулся, а цена ближе `StallAtr`·ATR к входу (В1 01:20);
   - `ADVERSE_FLOW` — цена против нас, а после входа пошли сделки в нашу сторону (В1 01:39);
   - добор (сценарий B) — цена ушла против на `AddStepPips`, перекос не сменился (В1 01:16).

**Отличия от автора, которые известны:** нет «исключить первый волатильный уровень», нет условия возврата в ЛРА
по перекосу при отходе, рост дельты с прошлого дня ищется только в пределах `CumLookback`, перекос цен берётся из
профиля по объёму, а не по сделкам; все числа порогов, кроме 50 пунктов, 50% дневного хода и 10–15 пунктов, — не авторские.

## 3. Параметры (Format → Strategies → LraTrader → Inputs)

| Параметр | По умолч. | Что делает |
|---|---|---|
| `CrowdMode` | CUM | CUM — кумулятивная дельта от начала роста; WINDOW — окно `ImbBars` |
| `CumLookback` | 12 | CUM: сколько часов назад искать начало роста |
| `CumWeight` | 0.05 | CUM: рост дельты / объём с начала роста |
| `ImbBars` | 2 | WINDOW: окно толпы, часов |
| `MinShare` | 0.05 | порог противоречия дельты по объёму; в WINDOW — ещё и минимальная доля дельты от объёма дня |
| `LevelImbPct` | 0.3 | цена перекошена, если (Ask−Bid)/(Ask+Bid) ≥ этого |
| `MinLevels` | 3 | сколько цен должно быть перекошено |
| `StallAtr` | 0.5 | WINDOW: допуск цены в сторону толпы; оба режима: «цена рядом с входом» для `DISSOLVED` |
| `StrongAtr` | 1.5 | WINDOW: сильное движение для сценария D |
| `FractalBars` | 2 | ширина фрактала для стопа и тейка |
| `SwingLookback` | 48 | глубина поиска фракталов, баров |
| `OffsetTicks` | 1 | отступ стопа и тейка за фрактал |
| `MaxStopPips` | 30 | самый дальний допустимый стоп |
| `MaxTakePips` | 15 | предел тейка первого контракта |
| `AddStepPips` | 10 | добор через столько пунктов против |
| `AddTargetMode` | SAME_TP | цель добора: SAME_TP — тейк первого; ENTRY1 — цена первого входа |
| `MaxRangePips` | 50 | высота диапазона ЛРА |
| `MinRangeBars` / `MinActiveBars` | 4 / 2 | длина диапазона / часов Европы-Америки в нём |
| `MaxRangeAgeBars` | 120 | сколько часов помнить диапазон |
| `LraMinDistPips` | 30 | второй контракт, только если POC дальше этого |
| `DayTargetShare` | 0.5 | второй контракт, только если POC ближе этой доли дневного хода |
| `AtrPeriod` | 14 | период часового ATR и число дней дневного хода |
| `PipSize` | 0.0001 | размер пункта |
| `CommissionUsd` | 0 | комиссия за контракт туда-обратно |
| `NewsWindows` | 14:30-15:30;19:00-21:00 | окна новостей, время Парижа |
| `LogDir` | D:\TradeLog\LRA | папка CSV |

После смены параметра старые CSV надо убрать из `LogDir`: советник не переписывает строки, которые уже есть в файле.

## 4. Что на графике

- Стрелка входа: синяя вверх — покупка, малиновая вниз — продажа; буква — книга (`A` — против толпы, `D` — по движению).
- Пока сделка открыта: серая линия — вход, красная — стоп (`SL`), зелёная — тейк (`TP1`, `TP2`).
- На выходе: пунктир от входа к цене выхода и подпись «причина ±пункты»: зелёная — плюс, красная — минус, серая — ноль.

## 5. Файлы в `D:\TradeLog\LRA`

| Файл | Строка = |
|---|---|
| `runs.csv` | запуск/остановка с параметрами, `VP_WAIT` / `VP_READY` |
| `signals_<символ>.csv` | каждый сигнал, в том числе пропущенный (`Taken`, `SkipReason`). В режиме CUM сигнал повторяется каждый час, пока держится рост |
| `trades.csv` | закрытая часть сделки: вход, выход, причина, пункты, USD |
| `ranges_<символ>.csv` | событие диапазона: NEW / DONE / EXPIRED |

`Source` = HIST (история) или LIVE (реальное время).

## 6. Записыватель BarRecorder

`src/BarRecorder.Indicator.MC.CS` → `Techniques\CS\BarRecorder.Indicator.CS`. Ставится на график с профилем
(Every 1 Bar) и пишет каждый закрытый бар в `<Dir>\<символ>_<Label>.csv`:
`Time,Symbol,Label,Open,High,Low,Close,Ask,Bid,Delta,Levels`, где `Levels` — `цена:ask:bid;...`.

Сейчас два графика `BP6Z26` 1 Hour: метка `TICKS` — профиль Ask vs Bid, метка `UPDN` — профиль Up vs Down Tick.
Файл только дописывается барами новее последней строки, чтобы не потерять бары старше месяца истории CQG.

## 7. Прогон без MultiCharts

`bash src/lra/sweep/run.sh` (из `atas-indicator-v1/multicharts`) — ядро советника по файлам записывателя
`D:\TradeLog\Bars\BP6Z26_TICKS.csv` и `BP6Z26_UPDN.csv`, перебор порогов по одному.
`... run.sh 'D:\TradeLog\Bars' only` — только настройки по умолчанию; `... cum` — перебор режима CUM;
`... frac` — стоп и тейк по фракталам. Другой символ — `SYM=EU6Z26 bash src/lra/sweep/run.sh ...`.
С настройками по умолчанию даёт то же, что MultiCharts, с разницей в 1–2 сделки (иначе считается часовой ATR).

Проверки по BP6Z26, 28.09–27.10 (около 500 часов с профилем):

| Что | Результат |
|---|---|
| `FractalBars` 1 / 2 / 3 | +50 / +60 / +22 п., просадка 33 / 17 / 36 |
| Стоп ≤ тейка, тейк ≥ 10 п., «следующий фрактал» | все хуже текущего |
| WINDOW → CUM (12 ч, вес 5%, строгая цена, уровни) | 21 сделка +60 п. → 13 сделок +114 п.; лучше в обеих половинах месяца |
| В MultiCharts, CUM | 14 сделок, 10 / 4, +126 п., +$788 |

За месяц — 13–25 сделок; разница меньше 20–30 пунктов может быть случайной. Пороги подбирать после 2–3 месяцев записи.

## 8. Сборка и тесты

Из `atas-indicator-v1/multicharts`, bash:
- `src/lra/tools/test.sh` — тесты ядра (`src/lra/tests/*.cs`);
- `src/lra/tools/bundle.sh` — собрать `src/LraTrader.Strategy.CS`;
- `src/lra/tools/build.sh <файл>` — проверка компиляции с библиотеками MultiCharts.
