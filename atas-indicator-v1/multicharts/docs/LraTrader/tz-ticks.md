# ТЗ: дисбалансы толпы по ценам и их отработка маркетмейкером (по тиковым данным)

Начато 2026-10-27. Идём по шагам, каждый шаг можно делать в отдельной сессии.
Статус шага меняем здесь же: `не начат` → `в работе` → `готов (дата, коммит)`.
Проверки данных и их результаты — [README.md §9](README.md#9-проверки-данных).

## 1. Цель

Поймать, на каких ценах толпа набирает позиции, и измерить, как маркетмейкер их отрабатывает:
выносит стопы толпы, возвращает цену к её входу или закрывает её позиции встречными сделками.
Сначала измерить на данных (шаги 2–3), только потом менять советник (шаг 4).

## 2. Что говорит автор

Ссылки: `В1 01:14:18` = видео 1, время в расшифровке `D:\Том Лексей\Том Лексей\Видео\*.full.txt`.

1. **Маркетмейкер один и идёт против большинства.** Единая система собирает все позиции в один портфель (В1 04:11–04:43).
   В полосе ±50 пунктов ему всё равно, где цена, сделки там «на удачу» (В1 01:12–01:14).
   Сделка — только когда сложился дисбаланс: тогда цена временно идёт против него (В1 01:14:18–01:15:01).
2. **Толпу видно по количеству сделок, а не по объёму.** Кумулятивная дельта по количеству сделок растёт,
   цена стоит или идёт против и не обновляет хай/лоу; по объёму перекоса может не быть (В4 02:28–04:26).
   «Дельта по объёму на месте, по количеству сделок растёт — повод искать продажи» (В2 07:05–07:35).
   100 сделок по 1 контракту надёжнее одной на 100 (В1 38:01–40:31).
3. **Перекос на нескольких ценах.** Одна цена — может быть закрытие позиций или стопы; против неё не входить,
   она годится только как причина выхода (В4 05:16–05:36, 08:03–08:22; В1 01:24:45–01:25:21).
4. **Вес — от начала роста.** «Было 300 контрактов с начала роста, из них 180 покупок — весомо» (В2 22:05–22:53).
   Дельту оценивать относительно объёма, «+100 при 62 000 — ничто» (В1 42:04–43:22).
5. **Время.** Чем дольше цена стоит при видимом перекосе, тем больше участников входят и тем вероятнее ход против них (В1 01:25:49–01:26:06).
6. **Отработка толпы маркетмейкером:**
   - вынос стопов: цена идёт за ближайший лоу/хай за толпой — наш тейк, 10–15 пунктов (В4 03:35–03:48; В1 01:15:15–01:15:41);
   - возврат к входу толпы, чтобы она закрылась в ноль; цена ушла против нас на 10–15 п., перекос не сменился —
     добавляемся, цель — возврат к ценам толпы (В1 01:16:15–01:17:28, 01:30:04).
7. **Отмена сценария:**
   - цена прошла уровень, за которым маркетмейкер «теряет» этих участников, — это стоп (В1 01:15:41–01:16:08, 01:34:07–01:34:36);
   - перекос «уравняли» новые позиции (В4 04:26–04:43);
   - цена идёт против нас, а в нашу сторону набегают участники — не добавляться, выходить (В1 01:17:38–01:18:51).
8. **Окна, на которые смотрит автор:** текущая сессия, последние 2 часа, две сессии, тиковый график (В2 00:00–03:56, 21:01).
9. **Мелкие сделки** — 1–3 контракта (В1 00:49–01:01).

## 4. Шаги

### Шаг 1. Данные — `в работе`

1. TickRecorder дописывает файл, а не перезаписывает (`src/TickRecorder.Indicator.MC.CS`).
   Файл `D:\TradeLog\Bars\<символ>_TRADES.csv`: `Time,Price,Size,Dir,Source`;
   `Size` — контракты, `Dir` = 1 вверх / −1 вниз, `Source` = HIST / LIVE.
   Сделки с одинаковым временем (до 0,001 с) не теряются и не дублируются: при запуске считается, сколько строк
   с последним временем уже в файле.
2. Тиковые графики `1 Tick` для `BP6Z26` и `EU6Z26`, история 30 дней, профиль выключен, на каждом TickRecorder.
   Графики держать открытыми — так история копится дольше месяца CQG.
3. Проверка 8 (README §9): совпадают ли сделки LIVE с теми же сделками из истории. **Сделано 2026-10-27: 512 из 512.**
   Снимок LIVE-сделок старой версии — `D:\TradeLog\Bars\check8\BP6Z26_TICK_live.csv`
   (старый формат `Time,Price,Volume,UpTicks,DownTicks,Source`, размер = UpTicks+DownTicks).
4. Проверка нового файла: нет дублей, нет пропусков — суммы по часам совпадают с `<символ>_TICKS.csv` (BarRecorder).
   **Сделано 2026-10-27 (проверка 9): фунт и евро, 504 часа из 504.** Осталось: дописывание после перезапуска графика без дублей.

Готово, когда: оба файла `_TRADES.csv` пишутся, история ≈ месяц, проверка 8 сделана, суммы по часам сходятся.

### Шаг 2. Находить зоны набора толпы — `не начат`

Отдельная программа по `_TRADES.csv`, без MultiCharts (рядом с `src/lra/sweep/`). Первый проход — с порогами
по умолчанию ниже, потом пороги перебираем. Сторона «толпа покупает» описана; «продаёт» — зеркально.

1. **Сделка.** Два варианта (README §9, проверка 6): каждое исполнение; группа «одно время до 0,001 с + одно направление».
   Отдельно считать мелкие сделки (≤ 3 контрактов, В1 00:49–01:01). Контракты — только для сравнения.
2. **Шаг проверки** — каждые 5 минут (автор решает внутри часа, а не на закрытии бара).
3. **Начало роста `s`.** Кумулятивная дельта по количеству сделок (вверх − вниз). `s` — её минимум за последние
   `L` = 12 часов, не ближе 30 минут к текущему моменту (В2 22:05: «подводим на начало роста»).
4. **Событие «толпа покупает»** в момент `t`, если всё сразу:
   - вес: (сделок вверх − вниз) / всех сделок с `s` ≥ `W` = 0.2 (пример автора 180 из 300 = перекос 60 из 300);
   - цена стоит: с `s` цена не поднялась выше хая за 60 минут до `s` — это уровень `H0` (В4 02:41–02:49);
   - несколько цен: ≥ 3 цены, где сделок вверх ≥ 60% и сделок ≥ 20 (В4 05:23–05:36);
   - не одна цена: на самую перекошенную цену приходится ≤ 50% перекоса (В4 08:03–08:22);
   - перекос по объёму не против: (Ask−Bid по контрактам) не в обратную сторону больше 5% (В1 01:35).
5. **Запись события** (одно на одно `s`, обновляется, пока условия держатся): символ, время первого срабатывания,
   сторона толпы, `s`, `H0`, цены зоны (перекошенные цены), сделок и контрактов в зоне, вес, длительность.

Готово, когда: есть список событий по обоим символам за месяц и на 3–5 из них я и пользователь сверили с графиком.

### Шаг 3. Как маркетмейкер отрабатывает событие — `не начат`

Уровни для события «толпа покупает» (наша сделка была бы продажей):
- **цель** — ближайший фрактал-лоу часовика ниже зоны (ширина 2, как в советнике): там стопы толпы (В4 03:35–03:48);
- **отмена** — `H0` + 1 тик: выше маркетмейкер «теряет» этих покупателей (В1 01:15:41–01:16:08).

Для каждого события из шага 2 посчитать, что было дальше (за 8, 24, 48 часов):

- дошла ли цена до цели (вынос стопов) и через сколько;
- пробила ли цена уровень отмены и через сколько;
- вернулась ли цена к ценам зоны после ухода от неё на ≥ 10 пунктов (выход толпы в ноль);
- закрылся ли перекос на ценах зоны встречными сделками: продаж после события ≥ 50% и ≥ 100% перекоса зоны; когда;
- что было первым из этих исходов; наибольший ход в нашу пользу и против нас, в пунктах.

Итог — таблица по фунту и евро отдельно: как часто каждый исход, за сколько времени, на сколько пунктов.
